## 3. Анализ сложности операций

| Операция | Сложность | Обоснование |
|---|---|---|
| Конструктор по умолчанию | O(1) | инициализация трёх полей (data, sz, cap) |
| Конструктор с параметром (размер) | O(n) | выделение памяти и value-инициализация n элементов |
| Конструктор копирования | O(n) | глубокое копирование n элементов |
| Конструктор перемещения | O(1) | копирование указателя и обнуление источника |
| Деструктор | O(n) | вызов деструкторов n элементов и освобождение памяти |
| Оператор присваивания копированием | O(n) | copy-and-swap: копирование и обмен |
| Оператор присваивания перемещением | O(1) | освобождение своих ресурсов и забирание чужих |
| operator[] | O(1) | адрес вычисляется как data + index |
| size() / capacity() / empty() | O(1) | возврат поля |
| push_back() | O(1) амортизированная | в худшем случае O(n) при расширении, но за счёт удвоения — амортизированно O(1) |
| pop_back() | O(1) | уменьшение счётчика sz |
| reserve(newCap) | O(n) | выделение памяти и перемещение/копирование n элементов |
| shrink_to_fit() | O(n) | выделение новой памяти, перенос элементов, удаление старой |
| clear() | O(1) | сброс sz (память не освобождается) |
| swap() | O(1) | обмен трёх полей |
| begin() / end() | O(1) | возврат указателя |

> **Замечание.** Сложность указана для типов фиксированного размера (int, double, char).  
> Для типов переменного размера (std::string) копирование в конструкторе даёт O(k), где k — размер значения.

## 5. Контрольные вопросы

### 1. Почему динамический массив называется «динамическим»?

Потому что его размер не фиксирован на этапе компиляции и может изменяться во время выполнения программы. Память выделяется в куче (heap), а не на стеке, что позволяет массиву расти по мере необходимости.

### 2. Что такое ёмкость (capacity) и чем она отличается от размера (size)?

size — количество фактически хранящихся элементов в контейнере. capacity — количество элементов, под которые выделена память. Всегда capacity >= size. Разница между ними — это свободное место, зарезервированное для будущих вставок без переаллокации.

### 3. Почему при расширении массива ёмкость удваивается, а не увеличивается на фиксированное число?

Удвоение обеспечивает амортизированную сложность O(1) для push_back. Если увеличивать ёмкость на константу, то при вставке n элементов суммарное время будет O(n²), так как переаллокация будет происходить на каждой константной границе. При удвоении переаллокации происходят логарифмически редко, и суммарное время составляет O(n).

### 4. Какова амортизированная сложность операции push_back? Почему?

O(1). Хотя отдельная операция при переполнении требует O(n) на копирование/перемещение элементов, такие дорогие операции происходят редко (при удвоении ёмкости). Суммарное время вставки n элементов составляет O(n), следовательно, в среднем на одну вставку приходится O(1).

### 5. Что такое «правило трёх»? Когда оно применяется?

Если класс управляет ресурсами (например, динамической памятью), то необходимо определить три специальных метода-члена: деструктор, конструктор копирования и оператор присваивания копированием. Применяется, когда класс владеет ресурсами, которые нужно освобождать, иначе возникает двойное освобождение или утечка памяти.

### 6. Что такое «правило пяти»? Чем оно отличается от «правила трёх»?

«Правило пяти» — это «правило трёх» плюс конструктор перемещения и оператор присваивания перемещением. Отличие в том, что «правило пяти» позволяет оптимизировать работу с временными объектами (rvalue), избегая дорогостоящего глубокого копирования за счёт «кражи» ресурсов.

### 7. В чём разница между конструктором копирования и оператором присваивания?

Конструктор копирования создаёт новый объект на основе существующего (инициализация). Оператор присваивания изменяет уже существующий объект, поэтому перед копированием необходимо освободить его старые ресурсы.

### 8. Зачем нужна проверка if (this != &other) в операторе присваивания?

Для защиты от самоприсваивания (например, v = v). Без этой проверки при освобождении памяти this->data мы удалим данные, которые затем попытаемся скопировать из other (который указывает на тот же объект), что приведёт к ошибке доступа к освобождённой памяти.

### 9. Что такое итератор? Как он связан с указателем?

Итератор — это объект, который обеспечивает последовательный обход элементов контейнера. Для Vector итератор является обёрткой над указателем (или самим указателем), так как память контейнера непрерывна. Итератор поддерживает операции инкремента, разыменования и сравнения.

### 10. Зачем нужны методы begin() и end()?

Они задают полуинтервал [begin, end) для обхода контейнера. begin() указывает на первый элемент, end() — на элемент, следующий за последним. Такой подход используется в range-based for и алгоритмах STL.

### 11. Как реализовать range-based for для своего контейнера?

Нужно реализовать методы begin() и end(), возвращающие итераторы (или указатели). Компилятор автоматически развернёт цикл for (auto x : v) в конструкцию с использованием этих методов.

### 12. Что такое «глубокое копирование»? Чем оно отличается от «поверхностного»?

Глубокое копирование выделяет новую память и копирует сами данные. Поверхностное копирование копирует только указатели, в результате чего два объекта указывают на одну и ту же область памяти, что приводит к двойному освобождению при удалении.

### 13. Что такое семантика перемещения и зачем она нужна?

Семантика перемещения позволяет «забрать» ресурсы у временного объекта (rvalue) вместо их копирования. Это нужно для оптимизации: вместо выделения новой памяти и копирования n элементов мы просто забираем указатель, что занимает O(1).

### 14. Почему конструктор перемещения помечается noexcept?

Это гарантирует, что при перемещении не будет выброшено исключение. std::vector при расширении использует перемещение только для типов с noexcept-конструктором перемещения (иначе использует копирование для строгой гарантии безопасности исключений).

### 15. Как правильно освобождать память в деструкторе?

Использовать delete[] data; (именно delete[], так как память выделялась через new[]). После освобождения желательно обнулить указатель, хотя в деструкторе это не обязательно, так как объект уничтожается.
